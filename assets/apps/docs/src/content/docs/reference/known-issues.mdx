Schola is honest about its rough edges. Every page in this guide that found
something unfinished or wrong in the code says so in a warning box. This page
collects all of those still open in one list, so a developer can plan the next
fixes and a school can judge the risks before going live. Each entry was
checked against the current code; anything fixed since a page was written is
listed under [Fixed in this release](#fixed-in-this-release) instead.

:::caution[Act on these first]
- **CI is switched off.** The GitHub Actions workflow sits in
  `_.github/workflows/ci.yml`; GitHub only runs workflows from `.github/`, so
  pushes and pull requests are not checked. See [below](#ci-does-not-run).
- **Security findings are not listed on this public site.** They are tracked in
  the private repository, in `docs/security-notes.md`.
:::

## Act on these first

### CI does not run

<Badge text="high" variant="danger" /> The workflow that runs typecheck, lint,
unit, integration and end-to-end tests is at `_.github/workflows/ci.yml`.
Commit `dff8604` renamed `.github` to `_.github`, and GitHub only runs
workflows from `.github/workflows/`.

**Impact.** No pull request or push is checked. Regressions reach `main`
unless someone runs `pnpm typecheck && pnpm lint && pnpm test` and
`pnpm test:e2e` by hand.

**What to do.** Rename the folder back to `.github` (and keep the secrets the
workflow needs in the repository's Actions settings, never in a file).

<SourceFile path="_.github/workflows/ci.yml" /> · [CI](/operations/ci/)

## Security and privacy

Security findings — anything that could expose data or accounts — are kept out
of this public site. They are tracked in the private repository, in
`docs/security-notes.md`, with their severity, impact and the code involved.
Review them before each production release.


## Data integrity

- <Badge text="high" variant="danger" /> **Rejecting a quick application
  switches off the applicant's personal account.** `rejectSchool` deactivates
  and soft-deletes the owner, which for an application from
  `/onboarding/school` is the person's existing account. **Impact:** the
  applicant loses their sign-in entirely and never sees the "not approved"
  screens. <SourceFile path="apps/api/src/modules/schools/schools.service.ts" symbol="rejectSchool" /> ·
  [Onboarding and welcome](/features/accounts/onboarding-and-welcome/#edge-cases-and-gotchas)
- <Badge text="medium" variant="caution" /> **Two accepted transfer links make
  two School Admins.** Older admin-transfer links stay valid, and accepting one
  removes School Admin only from the original nominator. **Impact:** ownership
  is ambiguous. <SourceFile path="apps/api/src/modules/admin-transfer/admin-transfer.service.ts" /> ·
  [Admin transfer](/features/school/admin-transfer/#edge-cases-and-gotchas)
- <Badge text="medium" variant="caution" /> **Stripe money for an already
  settled invoice is neither recorded nor refunded.** The webhook records
  `min(charged, remaining)` and stops at zero. **Impact:** a family can be
  charged twice with no record in Schola; refunds are manual in the Stripe
  Dashboard. <SourceFile path="apps/api/src/services/stripe/fulfill.ts" /> ·
  [Online payments](/features/finance/online-payments/)
- <Badge text="medium" variant="caution" /> **Moving a student hides their marks
  in the gradebook grid.** A mark keeps the `sectionId` it was first saved with,
  and the grid only shows marks of the current section. **Impact:** marks look
  missing and re-typing them doesn't fix the grid (results and report cards are
  still right). <SourceFile path="apps/api/src/modules/gradebook/grades.routes.ts" /> ·
  [Gradebook](/features/assessment/gradebook/#edge-cases-and-gotchas)
- <Badge text="medium" variant="caution" /> **An existing account added as a
  parent gets no Parent role.** `POST /parents` links the account to the record
  but grants no role. **Impact:** that person still lands on `/welcome` and
  can't see their children. <SourceFile path="apps/api/src/modules/people/parents.routes.ts" /> ·
  [Parents](/features/people/parents/)
- <Badge text="low" variant="note" /> **Enrolling an applicant is not one
  transaction.** Student, parent, enrollment and application are written one
  after another. **Impact:** an unexpected database error mid-way leaves partial
  records. <SourceFile path="apps/api/src/modules/operations/admissions.routes.ts" /> ·
  [Admissions](/features/campus/admissions/#edge-cases-and-gotchas)
- <Badge text="low" variant="note" /> **Audit entries are written by each route,
  after the change, without a transaction.** A failed insert is only logged,
  and a new route that forgets `auditLogger.log()` writes nothing. **Impact:**
  gaps in the audit trail are possible. <SourceFile path="apps/api/src/services/audit.service.ts" /> ·
  [Audit log (architecture)](/architecture/audit-log/#edge-cases-and-gotchas)
- <Badge text="low" variant="note" /> **The announcements Sent list depends on
  the audit log.** It is rebuilt from `audit_logs`. **Impact:** a failed audit
  write hides an announcement that was delivered.
  <SourceFile path="apps/api/src/modules/notifications/notifications.routes.ts" /> ·
  [Announcements](/features/communication/announcements/)
- <Badge text="low" variant="note" /> **Editing a bus route doesn't re-check its
  riders.** Seats can drop below the rider count, and renamed or removed stops
  stay on riders. **Impact:** cards like "30/20" and stops without a pickup
  time. <SourceFile path="apps/api/src/modules/operations/transport.routes.ts" /> ·
  [Transport](/features/campus/transport/#edge-cases-and-gotchas)
- <Badge text="low" variant="note" /> **A hostel room's Boys / Girls setting is
  not enforced.** **Impact:** a student can be placed in the wrong room; the
  desk must check by eye. <SourceFile path="apps/api/src/modules/operations/hostel.routes.ts" /> ·
  [Hostel](/features/campus/hostel/)
- <Badge text="low" variant="note" /> **A fee structure's class is not checked
  when billing.** `FeeStructure.classId` exists but is not on the form and
  Generate ignores it. **Impact:** any section can be billed with any structure.
  <SourceFile path="apps/api/src/modules/fees/fee-invoices.routes.ts" /> ·
  [Fees](/features/finance/fees/#edge-cases-and-gotchas)
- <Badge text="low" variant="note" /> **Role sync only adds.** Removing a key
  from a bundle in code doesn't remove it from schools that already have it.
  **Impact:** a revoked permission lingers until someone deletes the
  `role_permissions` rows. <SourceFile path="apps/api/src/services/rbac/seed.ts" /> ·
  [Permissions](/reference/permissions/)
- <Badge text="low" variant="note" /> **The Neon identity mirror is
  incomplete.** A password reset doesn't copy the new hash, and some sign-in
  paths (the Firebase endpoint) don't write to it. **Impact:** the mirror is not
  a reliable second source of truth. <SourceFile path="apps/api/src/services/identity-store.ts" /> ·
  [Neon Postgres](/setup/services/neon-postgres/)

## Fixed in this release

These were open when the guide was first written and are now fixed in the code.
The pages above describe the new behaviour.

**Permissions and access**

- The Accountant holds `academic_year:read`, `class:read`, `section:read`, `subject:read` and `staff_attendance:read:own`, so Fees no longer answers `403` and **My attendance** shows records.
- Teachers hold `academic_year:read`, so Classes and Exams no longer show a false "Create an academic year first".
- School Admin, Principal and Vice Principal hold `staff_attendance:read:own`; the start-up sync adds all new grants to existing schools.
- Each CSV export also needs its read key: fees `fee:read:tenant`, attendance `attendance:read:all`, payroll `salary:read:all`.
- The Gradebook is read-only (saved marks, "Read only", no inputs or Save) without `grade:enter`.

**Sign-in and sessions**

- Suspended, pending and rejected schools refuse sign-in with `403 INACTIVE_ACCOUNT` naming the status (unless the person has another active school), and end open sessions with `401`; status is cached for 10 seconds and cleared on suspend, reactivate, approve and reject.
- Google, Facebook and Firebase sign-in no longer re-activate inactive accounts (the redirect flow shows the `oauth_denied` message).
- The owner of a school still waiting for approval is told "Your school's application is waiting for approval. You'll get an email when it's approved." instead of "Account is not active." (password, Google and Facebook sign-in); suspended and rejected schools keep their wording.
- The lockout counter starts again from zero after a lock expires.
- `POST /auth/verify-email/resend` works signed out with `{ email }` (always `202`, one email per address per minute), and `/verify` has a "Send a new code" link.
- A password reset adds `password` to the account's `authProviders`.
- The admin-transfer link survives sign-in: the guard keeps path, query and hash, and `safeNextPath` allows same-origin relative paths only, in the guard and the login form.
- The development log prints cookie names, never cookie values.
- CSRF exempt paths are matched on the full path.

**Data and API behaviour**

- Query validation reaches handlers: `validate()` replaces `req.query` with the parsed values, so defaults and coercion apply, and `unreadOnly` uses `queryBoolean`.
- Exam and academic-year `PATCH` refuse an end before the start, including a single changed date checked against the stored one.
- Deleting a student removes their `student` sign-in role at the school.
- Re-enrolling a withdrawn or transferred student in the same year reopens the enrollment (`enrollment.reactivate`).
- Teacher and staff creation checks the employee ID (soft-deleted records included) before creating the account, and removes the account if the record still fails.
- Section capacity `0` means "no limit" in every API path (shared `_seats.ts`).
- Paying a cancelled payslip answers `409`.
- `GET /fee-invoices` returns `student: { name, admissionNumber }`.
- The audit-log `to` date includes the whole UTC day, on the school and platform logs.
- CSV exports prefix formula-leading cells (`=`, `+`, `-`, `@`, tab, CR) with `'`.
- Rejecting a school sends the rejection email (the owner is loaded before the soft-delete); signup, approval and rejection email failures are logged and the flow continues.
- Every email that follows a saved change is best-effort: adding a teacher, staff member or parent, inviting a platform user and creating a school directly answer `201` even when the email fails (the audit entry records `inviteEmail` / `ownerEmail: "failed"`), so a retry no longer hits "A user with this email already exists". Forgot password and the signed-out verification resend answer `202` either way. A signed-in resend and an admin transfer answer `503` with a clear message, and a transfer that can't be emailed is not started.
- Staff (with an email) and parents (new accounts) get the same set-password invite as teachers.
- Set-password invites have their own email, "Set your Schola password for *school*" with a **Set password** button, instead of the "Verify email" template; every email states its configured lifetime (`token-ttl.ts`), and the web pages no longer hard-code "1 hour" or "24 hours".
- The report card counts attendance up to today, like the attendance tab, so approved leave written ahead no longer lowers the rate.
- Audit snapshots store ids as 24-character strings and dates as ISO text; older `{"i0":…}` ids are shown as ids in the Before / After table.
- The audit-log **Action** filter (school and platform) matches the start of the action name — `school.` finds every school action — with the text escaped.
- `GET /salary-records` rows carry `employee: { name, employeeId }` (tenant-scoped, no personal data).
- `pnpm seed -- --reset` also removes the tutorial's Sunrise Academy (`sunrise.example` is a reserved demo domain) and schools of soft-deleted owners on those domains.

**Configuration and deployment**

- `SMTP_SECURE` reads `true` / `false` / `1` / `0` correctly (`envBoolean`).
- Production boot builds every model's indexes (`db-indexes.ts`); the `StaffAttendance` partial unique indexes and the token TTL indexes are fixed.
- The seed's "Term 1 — Final" starts in 15 days and ends in 24; the library E2E test uses "Holes".

**Web app**

- Fees: **Record payment** is a drawer that searches a student by name or admission number and offers all their open invoices with the balance pre-filled; each open invoice row has **Record**; the invoices table has a Student column; **Generate invoices** needs `fee_structure:create`, **Record** and **Pay** need `fee:collect`.
- Payroll: a **Mark paid** drawer (paid-on date, method, reference, notes) for `salary:pay`; Stripe **Pay** also needs `salary:pay`.
- Payroll runs: an **Employee** column (name, employee ID, Teacher or Staff), also named in the **Mark paid** drawer.
- Payslips print "Payment method: Bank transfer" and receipts "Bank transfer", "Cash", "Online", "Cheque" or "Other" instead of the stored code (`bank_transfer`).
- **Create class** and **Create section** work with "No class teacher" / "No section teacher"; the timetable's "Free period" / "No teacher" and the leave drawer's "Myself" no longer fail the ID check, and a picker problem now shows a message under the field.
- The admissions form saves with Date of birth blank.
- Transport **New route** ignores fully blank stop rows and explains a row with a time but no name.
- The leave drawer explains where requests and outcomes appear instead of promising a notification.
- The audit-log pages (school and platform) have loading, error with "Try again" and empty states, and a per-entry Before / After table.
- The platform dashboard's **Review queue** opens `/platform/approvals`.
- The home page JSON-LD no longer declares a `/search` `SearchAction`.
- **Load sample** applies only on pages the demo school fully covers; other pages show real data with a "Real data on this page." notice, and sample schools on platform pages have no detail links or actions.
- Students see a **Bus, room & library** card on their dashboard.
- The dashboard "Fees collected" chart was never broken — it animates in.
- The admissions **Enroll** drawer offers capacity-`0` sections ("· no limit") instead of greying them out as full.
- The sign-in form shows the API's reason for `INACTIVE_ACCOUNT` (pending approval, suspended school, …) instead of one generic message.
- Editing a student's, parent's, teacher's, staff member's or applicant's phone, date of birth or address no longer fails with "Something went wrong" (`CastError`): a schema plugin (`applyEncryptedUpdates` in `packages/db/src/models/encrypted-field.ts`) encrypts plaintext PII in query updates, and **My profile** saves a phone number.
- The dashboard and platform shells render a `<main id="main-content">` landmark.
- The end-to-end suite signs in after hydration and no longer depends on data earlier runs used up (offered applicants, free library copies, untaken registers).
