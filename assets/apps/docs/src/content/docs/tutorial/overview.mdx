This tutorial builds a real school on Schola, start to finish, using only the
web app. You play every part: the platform owner who approves schools, the
school owner who sets it up, the teacher, the accountant and the family. By the
end, **Sunrise Academy** has a timetable, a register, marks and a report card,
fees with receipts, and a month of payroll — and you have seen every portal.

Every chapter was performed for real against a running copy of Schola, and
the screenshots are from that run. The pages double as the script for the
walkthrough video "How to set up a school on Schola from scratch".

## Before you start

<Steps>

1. **Run the stack.** Follow [Installation](/setup/installation/) and
   [Running locally](/setup/running-locally/), then start everything with
   `pnpm dev`. The web app is at `http://localhost:3000` and the API at
   `http://localhost:8000/api/v1`.

2. **Load the demo data once.** Run `pnpm seed`. You need it for one account:
   the Super Admin `superadmin@schola.example` (password `Schola@2026`). It
   also gives you the demo school Greenfield International School, which the
   portals chapter borrows one student sign-in from.

3. **Check email.** With `RESEND_API_KEY` and `SMTP_HOST` both empty, the API
   uses the console transport: every email (verification codes, set-password
   links) is printed to the API log instead of being sent. That is the easiest
   setup for this tutorial. See [Email](/setup/services/email/).

4. **Optional — Stripe.** For the online payment in the fees chapter, set the
   Stripe test keys and let `pnpm dev` run `stripe listen`. See
   [Stripe](/setup/services/stripe/). Everything else works without it.

</Steps>

<Aside type="note" title="Real email providers and *.example addresses">
Every account in this tutorial uses the reserved domain `sunrise.example`, so
no real inbox is ever written to. When a real provider is configured (for
example a Resend key), sending to those addresses fails. Schola treats every
email that follows a saved change as best-effort: sign-up, approval, adding a
teacher, staff member or parent, and **Forgot?** all finish normally, and the
API log records that the email was not delivered. You then won't receive the
links — [chapter 5](/tutorial/add-people/) shows how to set a password without
them. With the console transport, every link is in the API log instead.
</Aside>

## Recording checklist

<CardGrid>
  <Card title="Browser" icon="laptop">
    Window size **1440 × 900**, zoom 100%. The screenshots in this tutorial
    use exactly that size.
  </Card>
  <Card title="Theme" icon="setting">
    Record in **light** mode (sun/moon button in the top bar). Optionally show
    the dark theme once, in the portals chapter.
  </Card>
  <Card title="Browser profiles" icon="puzzle">
    Use one profile per person so you never sign out mid-scene: **Platform**
    (Super Admin), **Owner** (Laila), **Teacher** (Omar), **Accountant**
    (Ethan), **Family** (Sara), and a spare one for Priya and the demo student.
  </Card>
  <Card title="Before each take" icon="approve-check">
    Close toasts, collapse nothing, and start each chapter on the page its
    first step names. Keep the API log visible in a second window if you use
    the console email transport.
  </Card>
</CardGrid>

<Aside type="tip" title="Names and dates">
The run behind these pages happened on Saturday, 7 November 2026. Use the same
names and values so your video matches the screenshots; dates such as "today"
will be your own day. If you record on a weekend, attendance still works — the
register simply records that date.
</Aside>
