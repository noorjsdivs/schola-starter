**Schola** is one web platform that runs the day-to-day work of a school. A
school signs up, the platform owner approves it, and from then on its staff,
students and parents do everything in one place: classes and timetables,
attendance, exams and report cards, fees and payroll, the library, transport
and the hostel. Many schools share the same Schola installation, but each one
only ever sees its own data. That is what "multi-tenant" means: every school is
a separate [tenant](/start-here/glossary/#tenant).

Schola's tagline is *School operations, beautifully simple.* The production
site lives at `https://schola.reactbd.com`.

## Who it is for

Schola has two layers of people. The **platform** layer is the company that
runs Schola. The **school** layer is everyone inside one school.

A person can also create a plain account before any school knows them. Until a
school adds them, they are a [visitor](/start-here/glossary/#visitor) and land
on <Route path="/welcome" />, where they can apply to bring their own school
onto Schola. [Roles at a glance](/start-here/roles-at-a-glance/) covers every
role in detail.

1. The school's owner fills in the "Bring a school" form on <Route path="/signup" />.
   The school is created with the status `pending_approval`.
2. The Super Admin opens <Route path="/platform/approvals" /> and approves it.
   The school becomes `active` and the owner becomes its School Admin.
3. The School Admin creates an academic year, subjects, classes and sections,
   then adds teachers, students, parents and staff.
4. From then on, the school runs on Schola every day.

[How Schola works](/start-here/how-schola-works/) explains this lifecycle,
including rejection and suspension.

## Try it in five minutes

The quickest way to understand Schola is to load the demo school and click
around. One command creates **Greenfield International School** with 500
students and a sign-in for every role (see [Demo data](/setup/demo-data/)).

<Steps>

1. Install and configure the project — [Installation](/setup/installation/).

2. Load the demo platform:

   ```sh
   pnpm seed
   ```

3. Start the web app and the API:

   ```sh
   pnpm dev
   ```

4. Open `http://localhost:3000/login` and sign in with a demo account.

</Steps>

<DemoLogin as="School Admin" email="admin@greenfield.example" go="/app">
  Every demo account uses the same password. Try the Super Admin
  (`superadmin@schola.example`) next to see the platform console.
</DemoLogin>

<Aside type="tip" title="No database at hand?">
Inside the school app, the "Load sample" button in the top bar swaps the page's
data for an in-browser demo school. It never touches the database, so it is
safe to press during a live demo. Press "Show real data" to switch back.
</Aside>

## What it is built with

Schola is a TypeScript monorepo managed with pnpm workspaces and Turborepo. The
browser talks to a Next.js web app, which forwards every `/api/*` request to a
separate Express API backed by MongoDB.

| Layer | Technology | Version in the repo |
|---|---|---|
| Web app (`apps/web`) | Next.js App Router, React | Next `16.4.3`, React `19.3.1` |
| Styling and UI | Tailwind CSS v4, shadcn/ui (New York style), lucide-react, Motion | Tailwind `^4.3` |
| Client state | TanStack Query (server state), Zustand (UI state), React Hook Form + Zod (forms) | Query `^5.105`, Zustand `^5.0` |
| Tables and charts | TanStack Table, Recharts | Table `^9.3`, Recharts `^3.10` |
| API (`apps/api`) | Node.js, Express, Zod validation, pino logging, Helmet, express-rate-limit | Node 22+, Express `^5.3` |
| School data | MongoDB with Mongoose | MongoDB 8, Mongoose `^9.11` |
| Identity mirror (optional) | Neon Postgres with Drizzle ORM | `drizzle-orm ^0.45` |
| Auth | argon2id passwords, JWT access token (`jose`), opaque refresh token, httpOnly cookies, CSRF double-submit | `argon2 ^0.45`, `jose ^6.2` |
| Federated sign-in | Google and Facebook OAuth redirect, Firebase Google sign-in | `firebase-admin ^14.5` |
| Email | Resend, with Nodemailer SMTP fallback and a console transport in development | `resend ^6.37` |
| Files and PDFs | ImageKit (images and video), `@react-pdf/renderer` (receipts, payslips, report cards) | `@react-pdf/renderer ^4.9` |
| Payments | Stripe Checkout with a webhook | `stripe 23.1.0` |
| Language | TypeScript, `strict` and `noUncheckedIndexedAccess` everywhere | `^6.0.3` |
| Tooling | pnpm, Turborepo, ESLint flat config, Prettier, husky + lint-staged | pnpm `9.15.0`, Turbo `^2.11`, ESLint `^10.14` |
| Tests | Vitest, Supertest + mongodb-memory-server, Playwright | Vitest `^5.0`, Playwright `^1.64` |
| This documentation (`apps/docs`) | Astro + Starlight | Astro `^7.4`, Starlight `^0.42` |

The versions come from each workspace's `package.json`. The tech stack is
locked by the original spec: nothing is swapped without
the product owner agreeing.

:::caution[Docs and code disagree in a few places]
- The original spec lists TanStack Table **v8**, but `apps/web/package.json` installs `@tanstack/react-table ^9.3.1`.
- The root `README.md` still mentions Next.js 16.2, TypeScript 5.7 and ESLint 9; the installed versions are Next 16.4, TypeScript 6.0 and ESLint 10.

This guide always follows the code.
:::
