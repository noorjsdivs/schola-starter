A **class** is a grade or level in one academic year — "Grade 3" in
2026-2027. A [section](/start-here/glossary/#section) is a group of students
inside a class — "Grade 3 · A" — and it is the unit the school actually runs:
attendance is taken per section, marks are entered per section, and each
student is **enrolled** in exactly one section per year. The Classes pages are
where the school builds that structure and fills it with students.

Two kinds of teacher assignment decide what a teacher "owns":

| Assignment | Set on | Gives the teacher |
|---|---|---|
| **Class teacher** (homeroom) | the class | Every section of that class — attendance for all of them |
| **Section teacher** | one section | That section — attendance and grade entry |

Together they make the teacher's **own sections**, which drive "My classes",
"Teaching today" on their dashboard and their attendance scope.

An **enrolment** ties a student to a section for one academic year, with an
optional roll number that orders the register. Its status is `active` until
the student is withdrawn.

## Step by step

<Tabs>
<TabItem label="Create a class">

<Steps>

1. Click **School setup → Classes & sections**, then **Add class**.
2. In the "New class" drawer ("A class belongs to one academic year. Sections
   are added inside it."), **Academic year** is already set to the current
   year.
3. Type **Name** `Grade 11` and an optional **Description**.
4. Pick a **Class teacher (optional)** — the list shows "Name (TCH-001)". The
   hint reads "The homeroom teacher. They can take attendance for every
   section of this class." Leave it on "No class teacher" if nobody leads the
   class yet; you can set one later with **Edit**.
5. Tick the **Subjects taught** (use "Filter subjects" to find them).
6. Click **Create class**. A toast says "Class created." and the class
   appears in the table with 0 sections.

</Steps>

</TabItem>
<TabItem label="Add sections">

<Steps>

1. Click the class name (or **⋯ → Open sections**). The detail page shows
   "No sections yet — Add at least one section (for example "A") before
   enrolling students."
2. Click **Add section**. In the drawer, type **Name** `A`, keep **Capacity**
   `40` ("0 means no limit.") and, if you like, pick a **Section teacher
   (optional)** ("They can take attendance and enter grades for this
   section."). "No section teacher" is fine.
3. Click **Create section**. A toast says "Section created." Repeat for `B`.
4. Click **Section A** in the table to select it. The roster card below
   reads "Section A — students".

</Steps>

</TabItem>
<TabItem label="Enrol students">

<Steps>

1. With a section selected, click **Enroll students**. The drawer is titled
   "Enroll into Grade 11 · A" and says how many seats are left.
2. Search with **Search name or admission no.** Only students **without a
   class this year** are listed; a student from last year shows "· was in
   *class*".
3. Tick the students. If you tick more than the seats left, a red line says
   "Only N seats left in Grade 11 · A." and the button is disabled.
4. Click **Enroll N students**. Students are enrolled one at a time; a toast
   says "Enrolled N students in Grade 11 · A." Any that fail are reported in
   a red toast with the first reason.
5. The roster now lists them, sorted by roll number then last name.

</Steps>

</TabItem>
<TabItem label="Move or withdraw">

<Steps>

1. Open **Grade 3**, select **Section A**, and open **⋯** on a student.
2. Choose **Move or set roll no.** The drawer "Move *name*" ("Change the
   section or roll number for this academic year.") offers every section of
   this year with its seat count; full sections are disabled and marked
   "— full".
3. Pick **Grade 3 · B** or change the **Roll number** and click **Save**. A
   toast says "Enrollment updated."
4. Or choose **Withdraw from section**. The dialog asks "Withdraw *name*?" —
   "They leave this section's roster and attendance register. Their student
   record and past attendance stay." Click **Withdraw**; a toast says "*Name*
   was removed from A."

</Steps>

</TabItem>
</Tabs>

## Every action on this screen

### Loading classes

<Api method="GET" path="classes" perm="class:read" /> <Api method="GET" path="classes/:id" perm="class:read" />

Query `academicYearId` filters by year. Each class comes back with its year,
class teacher, section count and student count. Sorted by name.

### "Add class" / "Edit class" / "Edit"

<Api method="POST" path="classes" perm="class:create" /> <Api method="PATCH" path="classes/:id" perm="class:update" />

| Field | Rule |
|---|---|
| Academic year | required; must belong to the school ("Academic year not found.") |
| Name | 1–60 characters; unique within the year ("Another record already uses this name.") |
| Description | optional, up to 500 characters |
| Class teacher | optional — "No class teacher" creates the class without one; a teacher of this school ("Teacher not found in this school."); choosing "No class teacher" when editing clears it |
| Subjects taught | any subjects of this school ("Subject not found.") |

Audit actions `class.create` and `class.update`. The API also offers a
dedicated endpoint to set only the class teacher (audit `class.assign_teacher`);
the page sets the teacher through the edit form instead.

<Api method="POST" path="classes/:id/assign-teacher" perm="class:assign_teacher" />

### "Delete" (class)

<Api method="DELETE" path="classes/:id" perm="class:delete" />

The dialog warns "Only classes without sections can be deleted. Delete its
sections first." The API refuses with "This class still has 2 sections.
Delete them first." Otherwise the class is soft-deleted (`class.delete`).

### Sections: load, "Add section", "Edit", "Delete"

<Api method="GET" path="sections" perm="section:read" /> <Api method="POST" path="sections" perm="section:create" /> <Api method="PATCH" path="sections/:id" perm="section:update" /> <Api method="DELETE" path="sections/:id" perm="section:delete" />

Name 1–20 characters, unique within the class; capacity a whole number
0–1000 (default 40, 0 = no limit); section teacher optional. Delete is refused
while students are enrolled: "25 students are enrolled in this section. Move
or withdraw them first." Audit actions `section.create`, `section.update`,
`section.delete`.

### The roster

<Api method="GET" path="students" perm="student:read" />

Called with `sectionId` and `pageSize=100`. Each student carries their
current enrolment (section, roll number).

### "Enroll students"

<Api method="POST" path="enrollments" perm="student:create" />

One request per ticked student, in sequence, so the capacity check is exact.
The API refuses when the section belongs to another year ("That section
belongs to a class in a different academic year."), when the student already
has an **active** enrolment that year ("Student is already enrolled for this
academic year.") or when the section is full ("Section A is full (30/30).
Raise its capacity or pick another section."; capacity `0` never fills).
Audit action `enrollment.create`.

A student who was withdrawn (or transferred) earlier in the same year
reappears in the picker and can be enrolled again: the API reopens their
existing enrolment in the chosen section, with a new roll number and
`enrolledAt`, and writes `enrollment.reactivate` with the before and after.

### "Move or set roll no." and "Withdraw from section"

<Api method="PATCH" path="enrollments/:id" perm="student:update" />

Move sends the new `sectionId` and/or `rollNumber` (the target must be in the
same year and have a free seat). Withdraw sends `{ "status": "withdrawn" }`,
which also stamps the end date. Audit action `enrollment.update`.

## Edge cases and gotchas

- **Names sort as text.** The list is sorted alphabetically, so Greenfield
  shows Grade 1, Grade 10, Grade 2, … Grade 9.
- **The enrol picker sees 100 students at a time.** It loads the first 100
  matches of your search and hides those already placed this year. In a large
  school, search for the student instead of scrolling.
- **The roster shows up to 100 students per section.**
- **Changing a class's year does not move its enrolments.** Enrolments keep
  the year they were made in.
- **A deleted name stays taken.** Like years and subjects, a deleted class or
  section still blocks its name in the same year or class ("Another record
  already uses this name.").
- **Teachers see every class.** Read access is school-wide; their *own*
  sections only matter for attendance and grade entry.
- **The empty teacher pickers.** "No class teacher" / "No section teacher" is
  an empty value in the form; the drawers turn it into "no teacher" before the
  shared schema checks it (`setValueAs: blankToUndefined`), and on **Edit**
  into `null`, which clears the teacher. Any problem with a picker shows as a
  red message under it. (Before this release the empty picker failed the ID
  check without a message, so **Create class** and **Create section** did
  nothing unless a teacher was picked.)
