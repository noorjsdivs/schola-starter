A new Schola database is empty: no schools, no people, not even a Super
Admin. The **demo seed** fills it with a realistic platform in about a minute,
so you can explore every screen, record a walkthrough video, or run the
end-to-end tests. It is the same data the rest of these docs refer to.

```sh
pnpm seed
```

Every demo account uses the password **`Schola@2026`**.

## Run it

<Steps>

1. Make sure `MONGODB_URI` and `ENCRYPTION_MASTER_KEY` are set in `test.env` (see [Installation](/setup/installation/)) and MongoDB is running. The seed reads the same env files as the API.

2. Run the seed from the repository root:

   ```sh
   pnpm seed
   ```

   The root script runs `pnpm --filter @schola/api run seed:demo`, which runs
   `tsx src/jobs/seed-demo.ts`.

3. Watch the progress. The seed prints each step, then a count of every record
   it created and the sign-in table:

   ```text
   Connecting to mongodb://localhost:27017/schola …
     Building the demo school…
     Creating 41 sign-in accounts…
     Inserting 2 academic years…
     …
   Done in …s.
          41  sign-in accounts
           4  schools
           …
   Sign in at /login with any of these accounts:
   ```

   A password inside the connection string is masked as `***`.

4. Start the apps with `pnpm dev` and sign in at `http://localhost:3000/login`.

</Steps>

## How it works

<Pipeline
  caption="What one run of pnpm seed does."
  steps={[
    { label: 'Check', icon: 'shield', note: 'env, password, NODE_ENV' },
    { label: 'Roles', icon: 'key', note: 'permissions and platform roles' },
    { label: 'Existing data?', icon: 'search', note: 'stop, or remove with --reset' },
    { label: 'Indexes', icon: 'database', note: 'create missing ones' },
    { label: 'Build', icon: 'layers', note: 'whole dataset in memory' },
    { label: 'Insert', icon: 'cloud-upload', note: 'accounts, schools, records' },
    { label: 'Audit', icon: 'scroll', note: 'one seed.demo entry' },
  ]}
/>

1. **Checks.** Refuses to run in production (see below), requires `ENCRYPTION_MASTER_KEY`, and checks the password against the normal password policy.
2. **Permissions and platform roles** are written, as the API does at start.
3. **Existing demo data** is looked up: any account on a reserved demo domain (`schola.example`, `greenfield.example`, `riverside.example`, `lakeside.example`, `hilltop.example`, and `sunrise.example` — the [tutorial](/tutorial/overview/)'s Sunrise Academy), soft-deleted ones included, and any school owned by one. If some exists, the seed stops — or removes it first with `--reset`.
4. **Indexes.** Every unique index is created before the bulk insert, so a fresh database enforces the same rules as a running one.
5. **Build.** The whole dataset is built in memory by a pure function, with every id assigned up front.
6. **Insert.** Accounts (all sharing one argon2id hash of the password), schools, the tenant roles of the approved schools, memberships, then every collection in dependency order, in chunks of 2,000.
7. **Identity mirror.** If `DATABASE_URL` is set, the accounts are also copied to Neon Postgres, as sign-up does.
8. **Audit.** One `seed.demo` entry with the counts.

The seed works across schools, so it writes with the models directly instead of
`withTenant`; every school document gets its `schoolId` from the builder.

## Options

```sh
pnpm seed -- --reset                     # remove the demo data, then seed a fresh copy
pnpm seed -- --password 'Another-Pass1'  # one password for every demo account
pnpm seed -- --students 300              # 20 to 600 students
pnpm seed -- --help                      # print the options
```

| Flag | Default | What it does |
|---|---|---|
| `--reset` | off | Removes the existing demo data first, then seeds again. |
| `--password <pw>` | `Schola@2026` | Password for every demo account. Must meet the password policy: 8–128 characters, with an uppercase letter, a lowercase letter and a digit. When you pass one, the sign-in table prints "(the --password you passed)" instead of the password. |
| `--students <n>` | `500` | Students in Greenfield, a whole number from 20 to 600 (20 sections × 30 seats). They are spread evenly across the sections. |
| `--allow-production` | off | Allows running with `NODE_ENV=production`. Must be combined with `--password`. |
| `--help`, `-h` | — | Prints the help text and exits. |

Any other flag stops the seed with `Unknown option` and the help text.

## Safety rules

- **It never duplicates.** Running `pnpm seed` twice stops with "Demo data is already in this database. Re-run with --reset to remove it and seed a fresh copy."
- **`--reset` removes only demo data:** the schools owned by demo-domain accounts — with every record stored under them, their roles, memberships and notifications — and the demo accounts with their sessions and email tokens. That includes schools built by hand on a reserved domain, such as the tutorial's Sunrise Academy, and schools whose owner is soft-deleted (a rejected application). An account on any other domain that belonged to a removed school keeps its sign-in and only loses that membership. Other schools and users are not touched. These records are deleted for real, not soft-deleted.
- **The audit log is kept.** Audit entries are append-only; `--reset` leaves them in place.
- **No real inbox is ever addressed.** Every demo email uses a reserved `.example` domain. Use `sunrise.example` for anything you build by hand that `--reset` should clean up.
- **Production is refused** unless you pass both `--allow-production` and your own strong `--password`. Never leave a known demo password on a public deployment.

<Aside type="danger" title="Check MONGODB_URI before you seed">
The seed writes to whatever database `MONGODB_URI` points at. Make sure
`test.env` names your local or development database, not a shared one.
</Aside>

## Troubleshooting

| Message | Cause | Fix |
|---|---|---|
| `ENCRYPTION_MASTER_KEY is not set` | No encryption key | Generate one with `openssl rand -base64 32`, put it in `test.env`. Use the same key the API runs with, or the encrypted fields will not decrypt. See [Encryption](/setup/services/encryption/). |
| `ENCRYPTION_MASTER_KEY must decode to 32 bytes` | The key is not 32 bytes of base64 | Generate it again with the command above. |
| `Demo data is already in this database` | You seeded before | `pnpm seed -- --reset`. |
| `Refusing to seed demo accounts with NODE_ENV=production` | `NODE_ENV` is `production` | Seed a development database, or pass `--allow-production --password '<strong password>'`. |
| `--password: Password must contain …` | The password fails the policy | Use 8+ characters with upper case, lower case and a digit. |
| `--students must be a whole number from 20 to 600` | Out of range | Pick a number from 20 to 600. |
| `querySrv ENOTFOUND …mongodb.net` or a timeout after 10 seconds | Wrong Atlas URI, or your IP is not allowed | Check `MONGODB_URI` and Atlas → Network Access. See [MongoDB](/setup/services/mongodb/). |
| `Index check skipped for …` | An existing index differs from the model | Only a warning: the data is still valid. Drop the old index if you want an exact match. |

## Demo data versus "Load sample"

The "Load sample" button in the school app's top bar is a different thing. It
swaps the page's data for a demo school generated **in the browser** and never
touches the database. It covers school setup, people, attendance, exams,
gradebook, remarks, reports and the dashboard; finance, facilities, leave,
admissions and personal pages always show real data. Use it for a quick look
without seeding; use `pnpm seed` for anything that needs real accounts, such
as signing in as a parent.
